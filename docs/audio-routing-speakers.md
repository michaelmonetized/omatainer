# Declared speakers

Routing owns `speakers::Layout`, `Speaker`, `Binding` and `OutputContract`. A saved `Model::speaker_layouts` binding attaches a layout to a retained graph identity. Missing bindings preserve the old mono/stereo defaults. A wide port does not establish speaker identity.

`Layout::StereoLfe` is FL, FR, LFE with WAVE mask `0xB`. `Layout::Surround51Side` is FL, FR, FC, LFE, SL, SR with mask `0x60F`. `Layout::Surround71` is FL, FR, FC, LFE, BL, BR, SL, SR with mask `0x63F`. The side layout is distinct from a back-speaker 5.1 mask, and the 7.1 order is distinct from older wide-speaker configurations. WAVE interleaving follows ascending mask-bit order; physical device indices may be nonconsecutive. These are [WAVEFORMATEXTENSIBLE file rules](https://learn.microsoft.com/en-us/windows/win32/api/mmreg/ns-mmreg-waveformatextensible) and [speaker configuration identities](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ksmedia/ns-ksmedia-ksaudio_channel_config), not panning or calibration rules.

`Model::channel_contract(Group::Output(id) | Group::Record(id) | Group::Input(id), encoded_count: u16) -> Result<OutputContract, String>` returns the actual encoded `channel_count`, ordered physical source `channels`, ordered encoded `speakers`, and `wave_mask`. Native wide delivery must match its explicit declared layout. Mono/stereo delivery is an explicit fold: LFE is excluded; mono averages the resulting stereo pair. Old mono duplication and stereo fold behavior remain unchanged.

The public delivery adapter remains `audio_delivery::output_contract(&State, &Export) -> Result<OutputContract, String>`. The contribution adapter remains `audio_delivery::render_selected(Captured, &Export, Option<&Selection>, &Path, bounds, &Arc<AtomicBool>, &Reporter)`. The renderer writes generic interleaved frames. Delivery owns encoded writers, variable headers, recovery and publication. A writer's mask/count check cannot establish the meaning of supplied samples; the graph's contract supplies that order.

Built-in stereo inserts process FL/FR. The dedicated LFE channel passes those stereo inserts without processing or an automatic 10 dB boost. Track, return and master faders, mute/solo gates, track crossfader assignment, causal routing and output safety apply to the complete bed. A shared native wide return must preserve the declared primary bed; auxiliary ports retain their independent identities. Use explicit reviewed maps for a format conversion.

Positional sends are explicit and default off. For 2.1, −1…1 automation/MIDI is −30°…30° across the front pair. For 5.1 it is −180°…180°, with chosen anchors SL −110°, FL −30°, FC 0°, FR 30°, SR 110°. For 7.1 the anchors are BL −150°, SL −90°, FL −30°, FC 0°, FR 30°, SR 90°, BR 150°. Each uses an adjacent equal-power pair across the rear seam. Gains use cosine/sine between adjacent anchors and never feed LFE. These angles are the software panner's policy. Existing sends retain their stereo balance policy. Explicit LFE maps with positional mode off retain unity digital gain. Track, scene and main beds remain stereo unless explicitly declared wide; mono aliases, returns and mono audio sources remain available.

The chosen 5.1 Lo/Ro fold is `L=FL+q*(FC+SL)`, `R=FR+q*(FC+SR)`, with `q=1/sqrt(2)` and LFE omitted. Mono averages that pair. No automatic normalization is applied. A mono bed feeds the center of a 5.1 bed, and equal-power fronts in 2.1. Speaker identity controls implicit and contribution conversion: a 2.1 LFE at logical index 2 moves to index 3 in 5.1. Existing explicit user channel maps remain explicit.

The chosen 7.1 Lo/Ro fold adds matching back channels at `q`: `L=FL+q*(FC+BL+SL)`, `R=FR+q*(FC+BR+SR)`. Conversion to a 5.1 side bed retains FL/FR/FC/LFE at unity and forms `SL=q*(BL+SL)`, `SR=q*(BR+SR)`. Conversion from 5.1 side to 7.1 preserves its side identities and leaves backs silent. These are distinct explicit conversion matrices; chaining reductions need not equal a direct fold. A mono bed feeds the center of 7.1. No automatic subwoofer boost or output normalization is introduced.

Headphone program and PFL folds run before their stereo monitor controls and output safety, preserving the original causal alignment. An explicit mono/stereo file export folds the already processed native output channels, after their per-channel safety. Consequently the headphone and file fold are distinct operations around the nonlinear safety stage; native full-bed live/offline samples remain the null-test contract.

Optional `Model::monitor_bass` is a chosen monitoring policy, default off: one-pole low-pass history `low += (1-exp(-2*pi*cutoff/rate))*(input-low)` at 20–200 Hz, complementary high pass on every full-range channel, and their averaged low pass added at the chosen sub level to the existing unity LFE. It runs only before live physical output safety. The offline graph, headphones and pre-monitor recording taps retain the declared bed. Mic/aux speech adds to FL/FR only; ducking covers the whole bed. No automatic crossover or 10 dB gain is imposed on native files.

Routing review exposes the canonical layout, physical order, named positional controls, monitor split and per-speaker Track/Scene/Main/send/return peaks. The existing typed graph transaction owns confirmation, Undo, capture and save/reopen; MIDI and beat automation retain stable send/return targets and normalized Pan values. Retired session IDs keep their own declarations; a reused slot starts with its new identity's default.
