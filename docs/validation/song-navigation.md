# Named song sections and loop navigation

Issue [#255](https://github.com/michaelmonetized/omatainer/issues/255) adds named musical locators and an Arrangement loop to the existing native transport. Open **Arrangement timeline → Song sections and loop**. Add, rename, move or delete sections by exact quarter-note beat, then choose **Save song sections** to publish one complete live metadata edit. Save the project to retain the sections on disk. Section IDs survive renaming, movement and sorting; deleted IDs are never reused within that song. Up to 256 named sections and 65,535 lifetime identities are supported. Names are visible UTF-8 text, bounded to 256 bytes.

Previous/Next and each named section use the selected timing: Global, Immediate, quarter-note divisions or one/two/four/eight actual bars. Bar timing follows pickup and meter changes. Stopped navigation is immediate. Playing navigation keeps the current position until the exact musical boundary. The queued destination and boundary are visible and can be cancelled. Beat and seconds entry remain double precision; seconds jumps are immediate. Missing destinations and destinations that exceed the song time limit refuse visibly and clear older queued movement. Producers reject nonfinite, zero-ID or unsupported command data before queue admission.

Set loop braces using their exact start/end beats, save them, then toggle the song loop. **Loop section to next** uses the selected section and its next distinct chronological locator as braces and schedules the section jump atomically. The last section needs another later locator. While the loop repeats, its time span follows the native conductor, including tempo changes; fractional sample overshoot is preserved rather than lost each pass. A normal song jump exits looping while retaining the braces. Native keyboard and assistive controls use the same buttons and commands. MIDI learn offers named section by stable ID, previous/next, loop toggle and cancel. Mapped navigation uses global timing and press edges; button release never causes a second jump.

The saved navigation model is prepared on a bounded worker and admitted against the exact song namespace, Undo epoch, reviewed model and loop flag. Cancelled, stale or invalid work keeps the current song. Metadata edits work during playback and clip recording in Studio mode; performance protection keeps its existing edit guard. Each edit and loop-switch change has an atomic native Undo/Redo inverse. Audio does no string/vector allocation or final reference destruction when applying metadata, jumping or wrapping; replaced ownership retires on workers.

Jumps and loop wraps use the existing native seek path. It releases old clip/Arrangement notes, restores destination MIDI state and preserves held live input owners until their own releases. It finishes the current clip recording take and turns clip recording off. Playback stays playing. Stop, explicit seek, project replacement, safety reset, metadata replacement and cancellation clear pending movement. Reopening never resumes a pending jump; the saved loop switch and braces wait for deliberate Play. This is Arrangement/Session navigation; DJ decks retain their separate transport and controls.

Native state schema 22 stores sections and braces. Omitted older defaults migrate, while older headers reject injected navigation fields, including null. MIDI preset schema 3 and preference schema 20 persist the new actions. Existing preset 1/2 and preference 19 encoder settings remain supported; old headers reject injected navigation actions and newer preset banks. Capture work stays closed for this qualification.
