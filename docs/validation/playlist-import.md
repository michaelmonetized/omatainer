# Reviewed local playlist import

Issue [#156](https://github.com/michaelmonetized/omatainer/issues/156) adds **Named crates → Import playlists**. Enter an absolute playlist filename and choose **Review playlist file**. Select the reviewed playlists, inspect every unresolved entry, and explicitly allow reported exclusions before **Import reviewed playlists**. Tracks and fresh static crates publish together through the existing catalog owner. The source playlist and audio are never rewritten or copied.

Supported formats are UTF-8/ASCII M3U and M3U8, including extended `#EXTINF` entries, and XML plist exports from Apple Music/iTunes. M3U paths are relative to the playlist directory or absolute local filenames. Local `file:` URIs support empty or localhost authority and percent encoding. Nonlocal URLs are reported as provider-only; no audio is downloaded. Legacy M3U encodings require re-export to UTF-8. Apple XML accepts UTF-8 and BOM-labelled UTF-16, built-in XML entities and numeric character references. External DTD identifiers are never fetched. Internal DTD subsets, custom entities, duplicate keys and malformed structure refuse review.

Apple's [export procedure](https://support.apple.com/guide/music/save-a-copy-of-your-playlists-mus27cd5060f/mac) produces references and metadata. The importer reads `Tracks` and ordered `Playlists`/`Playlist Items`, matches numeric Track IDs, and follows the [Apple plist vocabulary](https://www.apple.com/DTDs/PropertyList-1.0.dtd). Organizational folders and their persistent parent identities are retained. Smart playlists become static snapshots of the exported item list; their rules are not recreated. Missing IDs, missing local Locations, protected records, subscription/provider records and unsupported containers remain explicit excluded entries.

For paths from another machine, supply one explicit **Replace path prefix → With local directory** mapping. Windows `C:\Music` and `file://localhost/C:/Music/...` normalize to `C:/Music/...`; a mapping matches an exact component prefix. Mac absolute paths can be mapped the same way. Matching is case-sensitive. Parent traversal beneath a replacement prefix is refused. The review shows the resolved current local path before saving. No basename search, guessed relocation or content-based merge occurs.

Playlist membership retains first-occurrence order. Repeated references to the same canonical typed location produce one member in that playlist, with duplicate positions reported in review and their original ordered references retained in schema-18 import provenance. Different locations are not automatically merged by audio content. Existing exact catalog versions keep their metadata, preparation and locks. A catalog location containing changed media is excluded until its version is resolved separately. Import rechecks the playlist fingerprint, regular-file descriptors, removable-volume guards and catalog identities before the catalog save claim. A stale review refuses the transaction. Fingerprints are cache/stat identity guards, not cryptographic hashes; complete audio decoding remains a separate load/validation step.

Each review is bounded to 32 MiB of input, 128 total folder/playlist nodes and 4096 total playlist references. XML adds a 32-level nesting limit, 500000 parser-event limit and 16 MiB total decoded text budget; an individual scalar is capped at 256 KiB. Names are at most 256 UTF-8 bytes and labels/path references at most 4096. Exceeding a bound refuses the whole review without truncation. Unselected playlists create no crates except selected descendants’ required parent folders. Empty exported folders/playlists are retained. An unchanged source import reuses its durable source identity and keeps native renames/moves. Changed sources require an explicit new snapshot that retains the old crates. Sibling name conflicts are assigned a distinct name shown in review.

Parsing, container inspection, mount discovery and catalog saving run on the catalog worker. Review shares the existing optional indexing scheduler with a 256 MiB reservation and honors performance protection. Cancellation works before the publication claim; after that claim the actual persistence receipt decides the outcome. Closing the panel leaves an admitted job running. A committed durability warning must be checked by reopening the catalog before retrying.

Software fixtures cover Unicode, relative paths, percent-encoded URIs, Windows prefix mapping, UTF-16, order, duplicates, existing preparation, changed versions, malformed XML and the native review/save route. Local qualification also uses Michael's existing Grey Album M3U and upstream exported macOS/Windows XML fixtures from [Mixxx](https://github.com/mixxxdj/mixxx/tree/main/src/test/itunes) and [Stratify](https://github.com/jasonrudolph/stratify/blob/master/spec/fixtures/iTunes%20Music%20Library.xml). Downloaded third-party exports and private media stay in ignored qualification output; their source revision and checksums belong in the qualification receipt. Missing upstream audio remains unresolved; those fixtures do not prove a full source library was imported.

The combined producer/DJ work in [#511](https://github.com/michaelmonetized/omatainer/issues/511) extends this route with mounted-volume discovery, version-specific DJ exports and schema-18 provenance. See [DJ discovery and migration](dj-library-migration.md) for the current support matrix and qualification limits. Earlier receipts below remain historical evidence for their recorded source.
