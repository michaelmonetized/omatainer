# External MIDI clock following

The MIDI status panel now selects one connected input as the song clock, or **Internal**. Selection belongs to the current session and defaults to Internal on a new application/project. The panel exposes confirmed tempo, phase error, jitter, clock counts, reacquisitions, loss reason and backend timestamp quality. A port receiving Omatainer clock output cannot be selected as its echo source.

The ordinary private MIDI input worker retains the original callback timestamp, source identity, safety epoch and clock generation. Its independent bounded clock queue does not consume ordinary command capacity. Selected Start and Continue take effect on the next clock; Stop releases clip-owned notes and preserves live owners. Song Position Pointer uses MIDI sixteenths and is held while stopped or applied on the next clock while active. System realtime bytes may interleave within a position message without corrupting it; malformed/truncated position messages are refused. Internal mode retains the existing realtime command path.

Timing follows 40–240 BPM using a fixed-size trimmed interval estimate, bounded phase correction and one coherent per-sample musical step. Batched USB clocks, isolated missing pulses, sustained tempo changes and fresh slower/faster acquisition have distinct handling. A selected source can freewheel at its last tempo or stop the song after a 250–2,000 ms silence deadline. Retirement, input overflow, clock-output feedback and unsupported tempo are visible losses. Queued transport from a retired generation cannot restart the song; a selected Stop survives full input/clock queues.

Stored conductor maps remain unchanged while external timing drives song playback, clip capture and the metronome. Automatic musical loop wraps retain external phase. Local Play/Stop, seeking, tempo/conductor edits and deliberate locator jumps return to Internal. Project replacement and safety stop retire following. Unsynced DJ decks keep their independent transport; Transport can be selected as their sync leader when song-clock following is wanted. Native controls and status use normal command admission, confirmed snapshots and bounded status/follow replies.

Qualification uses generated timestamp streams, private MIDI workers, synthetic guarded outputs, the actual software renderer and OutputCallback PCM, and actual native egui/AccessKit actions. No physical audio/MIDI device, live capture, new OS GUI or listening pass is used. The independent stage GUI/follower and protected native session remain preserved. Physical captured/hardware clock acceptance remains open.

Protocol sources: [MIDI Association message overview](https://midi.org/about-midi-part-3midi-messages) and [MIDI Association discussion identifying Song Position Pointer units](https://midi.org/community/midi-software/midi-machine-control).
