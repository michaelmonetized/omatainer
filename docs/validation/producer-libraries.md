# Producer content discovery, preset retention and installed Pack relinking

This extends the [Ableton migration](ableton-migration.md) within [#511](https://github.com/michaelmonetized/omatainer/issues/511) and the same [PR #510](https://github.com/michaelmonetized/omatainer/pull/510). See the [support matrix and workflow](../ableton-migration.md#producer-libraries).

Producer searches reuse the existing paged, disposable, mount-aware discovery process. They recognize Sets, clip Sets, device presets, ordinary audio, installed manifests, Pack archives and native VST3 preset candidates. A producer cursor cannot be resumed as a DJ cursor. Limits, cancellation, symlink exclusions, unreadable paths and source fingerprints stay explicit; no audio decoder, plugin or vendor code runs during discovery.

Installed Pack review uses a separate disposable process and the actual observed metadata grammar. It retains declared identity, vendor/version, text, SHA-256, fingerprint and stable source identity. Selection is explicit and does not imply a native engine or redistribution permission. Source imports resolve matching Pack IDs and safe relative paths, embed verified referenced audio, retain original device dependencies, and recheck the reviewed installation before publication. Missing and mutated metadata are refused. Native archive validation requires no source installation. Migration schema 2/project state 32 preserve these records; prior migration schema 1 remains readable.

User device presets retain their full original XML and source IDs. A structural wrapper creates one native track without rewriting rack branches, macros, ranges, order, bypass, parameter or opaque state. Nested engine substitution remains unresolved. The actual native VST3 worker restores an independently authored top-level effect preset by exact class and original state.

Eight producer-content tests pass, including actual discovery and metadata processes, malformed/bounded manifests, cancellation, readonly identity, mutation, nested preset native reopen, Pack sample embedding, path escape rejection and native VST3 preset restore. Both actual library UI tests pass: review/acknowledge/select/import/publish, source-mutation refusal, running-session preservation and protected-work refusal. The earlier UI run exceeded its ten-second deadline; its failed log is retained. An unchanged isolated repeat passed, followed by the complete content/UI serial repeat (8 + 2 passes).

The new native binary also passes all eight prior migration workflows. Ordinary migration (10), DJ discovery (4) and selected-track merge (7) regressions pass; ignored native tests were explicitly run separately. The final extra content/UI tests use generation 5 with production worker generation 3; intervening source changes add test helpers/tests and source-inventory metadata only. [The receipt](producer-libraries-receipt.json) records exact sources, binaries, successful and failed logs, and archived executable hashes. These are local software/native-process results from unoptimized root-crate builds, not release performance or hardware proof.

The installed Live 11 inventory supplied readonly format-layout observations for `.adg`, `.adv`, `.alc` and Core Library metadata. No factory sounds or compiled scripts are public fixtures. Real user-authored Live 10/11 source playback comparisons, applicable source listening, actual connected-volume removal/remount, playback-impact qualification and the remaining controller/audio/live-release scope stay open. The installed powered-hub app and saved sessions remain preserved.
