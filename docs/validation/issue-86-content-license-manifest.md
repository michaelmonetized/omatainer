# Issue 86: shipped content and license records

The supported and tested release is native Linux aarch64 (Rust 1.98.0). The
packager also recognizes the Linux x86_64 target but that target was not built or
run for this change. Refreshing on another supported native target must resolve
and review that target's component graph and runtime notices.

## Provenance and supplied terms

`licenses/assets.json` is the reviewed factory/integration policy. The generated
`manifest.json` gives stable IDs, actual factory-member identities, source
locations and SHA-256 records, exact Cargo versions/features/checksums, four
embedded font records, and the Rust toolchain's own standard-library copyright
record. `notices.json` retains the complete notices indexed by their digest.

The factory drum kit, 48 pad samples, two stems, instrument settings and initial
MIDI patterns are generated by original MIT-licensed project code. No external
recordings, reference-product presets, impulse responses, ML models/weights or
proprietary SDKs were found in the shipped inventory. This does not claim
compatibility with, endorsement by, or content rights from any reference vendor.
System-selected fonts, imported media, controller firmware, Omarchy/Quickshell
and dynamically provided OS libraries are identified as external. Their terms
are not replaced by this manifest.

Font records use the actual `epaint_default_fonts` 0.32.3 files and their notices,
including available embedded name-table copyright strings. They distinguish
Hack's MIT/Bitstream Vera ancestry, Ubuntu Font Licence 1.0, Noto's OFL 1.1 and
John Slegers's MIT emoji-icon font. The font crate's code license is not used as
a substitute for those terms.

Cargo resolution is a conservative build/runtime component inventory, not a
claim that every optional module is linked into the binary. Crate archive URLs
and Cargo.lock SHA-256s retain exact source identities. Missing crate-root
licenses were recovered from the upstream commit in `.cargo_vcs_info.json`;
these records retain their immutable URLs. `hexf-parse` supplies its CC0 grant
in the published Cargo declaration; the full CC0 text is from SPDX's official
versioned license list. MPL components have explicit source-availability and
redistribution information, with unmodified source archive links. Rust's own
`COPYRIGHT-library.html` supplies the standard-library constituent notices.

Primary references checked while preparing the summaries:

- [Mozilla MPL 2.0 FAQ, especially distribution of compiled unmodified source](https://www.mozilla.org/en-US/MPL/2.0/FAQ/)
- [Ubuntu font information and license](https://design.ubuntu.com/font)
- [SIL's official OFL 1.1 text](https://openfontlicense.org/open-font-license-official-text/)
- [Hack's upstream license](https://github.com/source-foundry/Hack/blob/master/LICENSE.md)
- [SPDX's CC0 1.0 text](https://github.com/spdx/license-list-data/blob/v3.27.0/text/CC0-1.0.txt)

The complete retained licensor notices govern; UI summaries do not issue new
licenses or grant rights to unrelated user material.

## Release and installation contract

`python3 scripts/license-manifest.py update` explicitly refreshes reviewed
records from the offline, locked native Cargo graph and toolchain. New
components lacking notices fail until a maintainer supplies exact pinned
upstream records. Ordinary validation never downloads or invents permissions.
A source, source inventory, Cargo graph, feature, toolchain, integration asset or
notice change invalidates the old records. Refresh, review, then rebuild.

`check` validates those records. `package --binary PATH --destination NEW_DIR`
creates an immutable release directory containing the executable, the six actual
integration files, the manifest, notices and `release.json`. It refuses an
existing destination and uses Linux `renameat2(RENAME_NOREPLACE)` for publication,
including the destination-creation race. `verify-package --destination DIR`
checks exact membership and hashes without executing a downloaded artifact.
It verifies integrity against the included receipt, not publisher authenticity;
there is no new signing system.

For a locally built package or install, the tool additionally runs the native
executable's read-only `licenses --manifest` / `--notices` commands and compares
exact bytes. These commands do not open audio, MIDI, IPC or a GUI. A stale binary
cannot carry a newer manifest merely because the source tree was refreshed.

The existing transactional installer stages the same records under
`~/.local/share/omatainer/licenses`, validates the staged bytes, and rolls them
back with the binary/configuration on failure. Each retained installation journal
contains an independently verified `release/` payload with that release's
binary, records, exact SHA-256 receipt, source-file hashes,
Git revision/modified-source marker when available, and prior files. Existing
user configuration is explicitly outside the content license grant. Unrelated
plugin files remain preserved by the existing installer and are not represented
as supplied licensed assets.

## Verification

- Real headless egui frames open the shipped Content & licenses button, select
  Ubuntu by asset ID, expand its full notice, close and reopen without changing
  the project. Worker parse failure is persistent and readable; closing during
  parsing leaves ordinary controls usable.
- Renderer fixtures compare generated kit, pad-bank, session-stem and seeded
  pattern identities against manifest members. Schema/version/missing-record
  failures never turn into invented permission information.
- Seven private package test groups cover exact record retention/reopen; extra,
  missing, altered source/notice/package files; dependency-feature drift; stale
  embedded records; cancellation cleanup; racing destinations; key font/MPL
  terms, font-version review and standalone verification without a toolchain. Fourteen private installer groups cover successful/idempotent publication,
  prior-file preservation, errors, cancellation/rollback and recovery, including
  the new license artifacts and recovery without a working Rust toolchain.
- The 1.4 MB Rust runtime notice uses worker-prepared UTF-8 line ranges and
  virtual rows. A real egui fixture keeps rendered text below 64 KiB over 16
  frames while real renderer commands continue to advance.
- Final assembled `cargo test --offline -- --test-threads=4`: **571 passed,
  6 opt-in fixtures ignored**; `cargo build --offline` passed. The refreshed
  native inventory contains 315 manifest entries and 188 source files. A package
  made from that assembled native executable passes exact embedded-record byte
  comparisons and reopened membership/hash checks. The isolated implementation
  also passed a release-profile build and package verification. Seven package,
  fourteen transaction and eight executable-rollback test groups all pass on
  the assembled source. No user desktop configuration,
  live socket, real controller, external media license, x86_64 execution, or
  physical power-loss durability was tested by these fixtures.

The isolated scene-input panic-abort probe copies the same embedded license
records as the native source. Its actual CLI, IPC and renderer scene-boundary
checks pass after packaging integration; no desktop or hardware is opened.
