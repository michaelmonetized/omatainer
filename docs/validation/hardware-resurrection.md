Tracking: [issue #508](https://github.com/michaelmonetized/omatainer/issues/508). Base: `stack/remaining-backlog`, `1625ee063014a674d272f5d3fc01e80e8191fe2c`.

The original NS7 now has a native Linux ALSA driver. Omatainer has dedicated original-NS7 and DDJ-SP1 maps, a programmable MPD232 profile, controller feedback, periodic input reconnection, and IPC input/output counters. The qualification host is an Asahi ARM64 MacBook Pro running `7.1.13-3-2-ARCH`. The powered stage hubs and active 30-foot extensions remained connected during the tests.

## Transport and reset behavior

The NS7's vendor interfaces do not expose standard USB Audio/MIDI descriptors. The new driver owns both interfaces, registers ordinary ALSA raw MIDI and PCM, validates high-speed endpoint layout, preserves the manufacturer's status bits and uses its frequency setup sequence. It supports four S32_LE playback channels and two S32_LE capture channels, with 24 significant bits at 44,100 Hz. It strips the MIDI transport padding, bounds every transfer, and acknowledges output payloads only after complete USB writes.

The initial firmware transport accepted writes while its audio clock returned zero-length/zero-valued feedback. Setting only output/capture endpoint rates did not resolve that state. Manufacturer 3.3.11 also sets the clock endpoint's rate. The completed rate sequence and a targeted USB reset started real clock and capture transfers. The driver now verifies rate readback and requires a valid clock within 500 ms of preparation.

The original NS7 stopped returning panel MIDI when the timed playback fixture closed, despite its MIDI input remaining subscribed with no USB errors. Opening a silent PCM stream immediately restored input. The driver now holds the shared clock for MIDI clients as well as prepared PCM streams. With playback inactive it sends zero samples; capture without a recorder is discarded. Closing playback leaves panel input live, and closing the last MIDI/PCM owner stops the clock.

On a targeted USB reset, audio URBs and MIDI transfers stop before reset; MIDI and its silent clock resume afterward without changing the ALSA port. Active PCM reports an XRUN. Omatainer records the backend error and stops the interrupted output through its existing audio owner. Reopen the output after reset. Resets do not automatically resume a performance.

The firmware emits occasional positive clock packets below 43 frames during initialization before its normal 43–46 frame millisecond clock begins. USB capture established those startup packets. They are discarded and counted as `pcm_feedback_partial` while both PCM directions are inactive; they do not satisfy startup validation. Malformed packets and running-stream clock faults remain errors.

The installer builds and tests locally, links the module into the running kernel's module catalog and loads it through its device alias. `--reset` adds one reset specifically for `15e4:0071`. Reinstall after kernel upgrades; this is not a DKMS package. Keep the checkout/module path in place.

## Controller behavior

DDJ-SP1 selection precedes the broad DDJ matcher. Its four wire deck banks mirror Omatainer's two decks. Hotcue pads, separate shifted deletion notes, loop controls, browser navigation, loading and paired 14-bit FX controls use the official addresses. Select the SP1's documented non-Serato MIDI utility setting when using Omatainer. Other pad modes and unmapped surface notes are ignored. Application-connect, Sync, loop and hotcue LEDs follow engine state outside the audio callback.

Original NS7 deck controls share MIDI channel 1 with separate note addresses. Its wheel CCs carry wrapping encoder counts; each source keeps independent history and clears it across input epochs. Trim and channel faders have separate engine state, so changing trim cannot reopen a closed fader. Feedback uses the actual Play, transport Cue and Sync LED CCs; the preliminary legacy mapping's supposed headphone Cue addresses were incorrect. The right Loop Out note is `0x4a`, and holding Delete modifies that deck's hotcues. Unknown browser messages and uncertain legacy addresses remain unqualified.

## Original NS7 motor transport and supplied-file playback

A bounded muted check started the left motor for six seconds, stopped it, then started and stopped the right motor. The user confirmed both moved in that order and stopped afterward, with both slipmat/vinyl assemblies installed. Channel-one CC 65/75 start the left/right motor; CC 66/76 stop them instantly. The returned spindle stream approaches 1,000 pitch-bend position reports per second for each moving deck. These physical results confirm the documented original-NS7 motor addresses; no firmware flash, RPM change or reverse command was sent. The start/stop commands are also described in [DJ Quartz's first-hand protocol notes](https://www.virtualdj.com/forums/118566/Old_versions/NS7_works_perfectly_with_6_0_3_and_both_PC___MAC_.html?page=6).

Omatainer's output worker follows each renderer-confirmed deck's Play/Pause and Vinyl state with edge-triggered motor commands. Repeated starts work after repeated stops. Recovery or a completed safety stop prevents motor start, and retiring an output connection sends stop commands to both motors. The worker checks updates every 16 ms. The user confirmed the application turns the physical platters and plays the supplied track through the PA. That first build did not scratch, its decorative display rotation was too slow, and its eight-Hz state publication visibly stepped.

The correction accumulates all wrapping CC 0/2 encoder ticks with their input callback times. The measured full forward/backward turns were close to 3,600 counts, and free rotation returned about 1,000 reports per second. The decoder hands accumulated movement to the audio owner at most once per four milliseconds; it does not discard angular displacement or flood the ordinary command queue. The pitch-bend companion is consumed rather than treated as a jog or guessed angular low word. Its clock units have not been established. A held record expires the velocity estimate and produces silence while Play remains armed. Forward and reverse movement use the same source clock; pausing permits manual vinyl movement. Input retirement releases only its spindle owner and stops that deck, and performance recovery clears spindle state. Audio tempo remains independent of the physical display angle.

The display uses measured accumulated turns and signed rotation, replacing the previous 18 turns per whole track. Renderer publication now targets 60 Hz, with at most 25 ms of display prediction between captured frames. Prediction modifies only the platter's drawing copy; source receipts, history and command guards retain actual captured state. The user confirmed stopping, forward/reverse scratching, matching platter speed and smooth display, then reported a continuous dragging sound on both decks even without contact. The first scratch clock replaced audio position on each input update, allowing USB timing jitter to splice the waveform. The subsequent correction integrates signed velocity continuously, estimates velocity from up to 32 ms of encoder history, and ramps speed over one millisecond. Reversing direction clears the forward history. Movement expires after 12–50 ms, allowing the four-ms command cadence and native audio period to pass short USB delivery gaps. Encoder updates continue to position the display directly. Listening acceptance of this audio correction, exact marker alignment, acoustic latency and extended turntable performance remain open.

Explicit `ctl deck-load A|B /absolute/file.mp3` requests capture local file identity and enter the normal asynchronous GUI loader, preserving deck-load locks and library selection. Two supplied MP3s were extracted into ignored project artifacts and loaded successfully in the visible installed GUI. The first live check starts deck A at master 0.04, with crossfader left and deck B paused. Application and native driver receipts remain distinct from the user's PA listening confirmation.

NS7 HEADPHONE MIX CC `0x12` blends the two equalized decks before their channel faders. HEADPHONE MODE note zero selects that blend or the audience master. The user's labelled MASTER→CH1/CH2 capture established note-off/zero for MASTER and note-on/nonzero for CH1/CH2; the decoder uses absolute positions rather than toggling state. Front-panel headphone volume CC `0x42` controls only the headphone pair. Omatainer enables that pair only on the original native NS7 ALSA output with four channels, using outputs 3/4; the audience pair stays on 1/2. Explicit user output aliases retain priority. Headphone volume starts at zero until its knob sends a value. Five-millisecond gain ramps and the shared emergency-silence envelope cover the pair, without allocation in warm audio rendering. Tests verify that moving headphone controls leaves the audience samples unchanged, that a closed channel remains available before its fader, and that Master monitoring does not reopen closed channels.

With the stage amps off and headphones in the NS7's 3.5 mm socket, the user identified raw four-channel beeps as output 3 in the left ear and output 4 in the right. After reconnecting an earpiece, the user confirmed Omatainer's low/high deck tones in both ears as HEADPHONE MIX moved. The first mode mapping reversed behaviour after moving the switch; that prompted the labelled capture and polarity correction. The earlier 180-second listening runs retained zero backend errors but recorded up to three callback deadline overruns while builds ran and the test process inherited a reduced scheduling priority. These are listening receipts, not a zero-overrun stage-performance guarantee.

APC original and mkII maps remain separate. Feedback requests the standard MIDI identity once per output connection, introduces the mkII host mode before LED messages, and mirrors occupied/playing clip state with each model's palette. Discovery excludes Omatainer's own ports, preventing recursive connections to its virtual inputs/outputs. Input policy also limits feedback connections. Performance protection gates automatic device changes.

The MPD232 allows each pad, knob, fader and switch to be programmed. Its profile preserves every incoming musical note, channel and velocity rather than consuming eight notes as MPK hotcues. Assign configurable controls through MIDI learn and save the assignments. MIDI Start/Stop and Clock retain the existing transport handlers; MMC is not mapped to transport. Its output owner supports the standard identity request; proprietary LED/program writes are not implemented. No software change has been demonstrated to fix its display restarts. The manufacturer's power specification is 6 V DC, 1 A, center-positive for its optional adapter; its manual also requires a powered hub for USB power.

MPD232 was absent from some instantaneous inventories because it repeatedly disappears between enumerations. Live sampling found USB power management set to `on`, runtime state `active`, and zero suspended time before each disconnection. Autosuspend was not triggering these observed restarts. Its firmware declares 500 mA bus power and has a malformed HID endpoint count; ignoring HID earlier did not stop the cycling. Its Omatainer inputs were excluded during the live reset observation. Its direct ALSA identity reply reports version bytes `01 00 00 00`. The official 1.0.1 firmware package and updater were obtained and inspected, but no firmware write or persistent HID quirk was applied. The user deferred the short-cable baseline.

- [Numark NS7 reference manual](https://www.numark.com/images/product_downloads/ns7_reference_manual___v1.1.pdf): physical controls and audio connections.
- [Mixxx original NS7 mapping](https://github.com/mixxxdj/mixxx/blob/main/res/controllers/Numark%20NS7.midi.xml) and [wheel script](https://github.com/mixxxdj/mixxx/blob/main/res/controllers/Numark-NS7-scripts.js): original wire controls. Its preliminary mapping contains conflicting legacy addresses; those were not copied.
- [DJ QUARTZ NS7 MIDI chart](https://cdck-file-uploads-global.s3.dualstack.us-west-2.amazonaws.com/free1/uploads/mixxx/original/2X/e/e56af08404ee1c2f7703c40eae60382d94183739.pdf) and [b1shop's original MIDI-OX measurements](https://virtualdj.com/forums/109729/Old_versions/Virtual_DJ6_and_Numark_NS7_(genelar_topic).html?page=1): headphone controls, Loop Out, Delete, and transport LED addresses. The raw trace distinguishes headphone mode note zero from meter mode note one; the chart duplicates that address. Physical Cue and wheel captures corroborate the selected wire messages.
- [Pioneer DDJ-SP1 official MIDI list](https://downloads.support.alphatheta.com/software_info/dj-controllers/DDJ-SP1/DDJ-SP1_List_of_MIDI_Messages_E.pdf): deck banks, shifted pads, browser, FX and LED messages.
- [Akai MPD232 user guide](https://cdn.inmusicbrands.com/akai/attachments/MPD232/MPD232-User_Guide-v1.1.pdf): programmable notes/controls, USB ports, transport modes and power.
- [Akai APC40 mkII protocol v1.2](https://cdn.inmusicbrands.com/akai/attachments/apc40II/APC40Mk2_Communications_Protocol_v1.2.pdf): host-mode introduction, Generic mode's local track selection, separate clip addresses and RGB palette.

This establishes connected I/O, the stated physical checks and software behavior. A full stage-performance acceptance test remains open. The initial native fixture used 2,048 frames; current scratching uses 512 frames with a 128-frame period. Build-load underruns have stopped output at the smaller buffer. An initial corrected GUI later exited with SIGKILL after a one-run real-time scheduling trial. No core dump or out-of-memory kill was recorded; the cause is unconfirmed. The current GUI runs under `omatainer-ns7-testdrive.service` with normal scheduling. Sustained low-latency performance and listening acceptance of the continuous audio-clock correction remain open.
