# VST3 processors in native projects and routing

This delivers the graph and project integration inside [#511](https://github.com/michaelmonetized/omatainer/issues/511) and the single [PR #510](https://github.com/michaelmonetized/omatainer/pull/510). It does not complete the remaining migration, controller or live-release qualification.

Preferences → VST3 plugins offers **Use as track instrument** and **Append track effect** for an already catalogued class. Both create a routing draft for the selected track. Review, cancel or apply the draft in Audio routing. Applying creates one undoable graph transaction; adding a second effect preserves chain order. Catalogued processors remain usable during a background scan. Protected performance defers processor creation and editor opening.

Instruments receive the track's Session, Arrangement and physical channel MIDI, then feed its native mixer/effects. Instrument audio works when physical input monitoring is Off. Physical note releases keep their original destination after track selection changes. Shared clip and physical gates prevent one owner from releasing another. Full graph replacement and panic release notes actually sent to a processor. Missing instruments remain silent rather than substituting the built-in synth.

Audio effects use explicitly mapped bus/channel indices, including sidechains and auxiliary outputs. The worker enables declared audio buses, including buses initially inactive. A track effect inserted after its mixer follows that track's current scene send; every other route remains explicit. Bypass delays the main dry input by the processor's complete reported delay. Sidechains are never echoed into dry auxiliary outputs; bypassed instruments are silent.

Each worker reports its native latency and carries the upstream delay of the input block it actually processed. Graph compensation adopts the delay attached to the arriving audio before gathering parallel inputs. Automation includes block endpoints, internal envelope corners and seeks at sample offsets; track MIDI has a bounded upstream-delay queue. Parallel cancellation tests use exactly representable impulses and verify zero residual at the fixed offline output time, including a native 64-sample latency change. Offline delivery owns separate workers, waits outside the callback, holds a reserved terminal delay and trims startup once. Missing or failed enabled processors prevent publication. Live transitions use the existing bounded delay blend; physical recording placement and live listening remain open qualification.

The audio endpoint owns eight preallocated packets and bounded SPSC queues. Its bridge adds 768 samples at every sample rate; native processor latency is additional. The callback does not call a plugin, send IPC, wait, allocate or free. Late audio is silent at its intended time and increments the visible counter. Preparation bounds total delay histories to 64 MiB before opening workers. Sample-rate changes checkpoint live opaque state and rebuild prepared processors off the callback. An incompatible history reconstruction prunes history through the existing retirement path instead of panicking.

Native project state version 29 and graph version 3 preserve class/version/binary identity, opaque component/controller state, bus shapes, track bindings, bypass, reported latency, manual normalized values and automation. Older project versions refuse injected plugin fields. A graph holds at most 32 processors, eight buses and 32 channels per direction, 128 retained manual parameters and 128 automation lanes per processor, with 16384 points per processor. Opaque state is capped at 8 MiB per processor; retained processor heap and encoded processor metadata each have a separate 32 MiB limit. Routing review also checks the complete native metadata limit before admission. Save capture uses the isolated owner's current state after already submitted blocks. Missing/version-mismatched processors keep their prior state and an actionable diagnostic through reopen.

Audio routing exposes a bounded generic parameter editor, bypass, current class/version/bus metadata, latency, missed blocks and processor/editor errors. Generic edits have renderer-owned undo/redo and gesture grouping. Controller observations refresh their normalized values. Generic edits are disabled while a native editor owns editing. Ordinary editor refusals preserve the healthy audio process; malformed responses, crashes and timeouts still retire it. The worker services Linux editor timers/file descriptors while the editor is open and handles user closure.

The host currently routes MIDI channel input on event bus zero. Graph MIDI output chains, additional event buses, SysEx and typed note-expression interchange are not implemented. AU, VST2, foreign operating-system bundles and incompatible CPU architectures remain unsupported with the scanner's explicit diagnostics. This milestone does not make Ableton stock devices or Packs native plugins, and does not yet import ALS plugin state.

Validation uses our own MIT contract effect/instrument against pinned Steinberg SDK 3.8.1, plus privately built GPL Nekobi and MVerb. The independent instrument/effect chain produces audio in the actual native renderer and retains the reverb tail after source release. Original fixtures cover inactive sidechains/outputs, transport context, bypass, automatic PDC, automation corners, original note ownership, manual undo, panic, native save/reopen, missing/versioned state, cancellation, storage admission and rate reconstruction. The browser/draft/apply/cancel/undo workflow uses actual egui/AccessKit widgets. The native MVerb editor is opened from those widgets on an independent authenticated Xvfb display, rendered, inspected and closed; the processor survives. The desktop Xwayland attempt failed separately, and the first independent screenshot exposed the missing editor-loop service before it was fixed.

[The graph receipt](vst3-graph-receipt.json) records binaries, source and fixture hashes, logs and exact successful selectors. Private executables, plugin bundles, screenshots, failed trials and lossless executable archives stay in ignored project-local validation storage. These are local software and native-process results. The installed powered-hub application and saved user sessions were preserved; this is not installed-app, hardware-loopback, physical-control, audible-listening or stage-quality acceptance. See the earlier dated [processor/scanner foundation](vst3-core.md) and [latency qualification](graph-latency.md).
