# Isolated VST3 processor and scanner foundation

This is an implementation milestone inside combined [#511](https://github.com/michaelmonetized/omatainer/issues/511) and the one PR [#510](https://github.com/michaelmonetized/omatainer/pull/510). It does not complete the producer, controller or audio-release scope.

Preferences → VST3 plugins opens the native catalog. Add absolute plugin folders, scan changed bundles, inspect each class/CPU/version/bus/parameter result, cancel, reload the saved catalog, retry quarantined binaries or blacklist/allow a bundle. Startup reads only the retained catalog; it does not instantiate plugins. The performance work permit cancels scans when protection is entered. Existing known records remain available during background work.

Traversal, bundle hashing and plugin introspection run in disposable processes. Each exchange has a ten-second deadline; cancellation is polled every millisecond. Worker death and malformed replies become errors. Processes are killed without blocking on an uninterruptible wait; a bounded owner reaps them separately. At most 96 plugin workers, including retiring processes, can exist. The private descriptor-three socket uses bounded length-prefixed JSON, independent of vendor stdout/stderr; helpers open no Omatainer audio/MIDI device. Parent-death signals retire helpers with their owner.

The catalog supports 64 configured roots, 4096 retained bundles, 100000 traversed entries, directory depth 16 and 16 MiB of retained data. Each inspected bundle is bounded to 4096 files, 128 MiB per file and 512 MiB total. Symlink/file bundles are refused. Native 64-bit little-endian ELF and CPU architecture are checked before loading. Content digests cover relative filenames and bytes. A changed bundle gets a fresh probe; an unchanged failed binary stays quarantined until explicit retry. Each bundle can advertise up to 64 processor classes, eight audio buses and 32 channels per direction, and 8192 parameters per class. Requests/replies are capped at 32 MiB; state is capped at 8 MiB. Catalog replacement checks the previous generation and preserves it on cancellation or pre-replacement failure. Invalid catalog data is refused and can be explicitly reloaded after correction.

The worker can load a chosen class, preserve its component/controller state through a versioned codec, process all bus/channel indices, queue sample-offset MIDI and normalized parameter points, seek exact sample/quarter-note positions, update tempo/meter/playing context, report latency/tails/restart flags and own a standalone native editor. Loading requires exact saved class, plugin version and content identity. This prevents a display-name match from silently replacing the sound. AU, VST2, Windows and incompatible CPU bundles are diagnosed rather than loaded.

The processor bridge owns eight preallocated packets and bounded SPSC queues. Audio copies samples/events; a broker owns blocking IPC and the SDK. Output has exactly three 256-frame blocks of bridge delay plus the plugin-reported latency. Late blocks produce silence at their intended time rather than shifting musical position. State capture waits outside audio/UI for already-submitted blocks. These APIs are not yet wired into Omatainer's project and graph. Final graph integration must route sidechains and every output explicitly, feed automatic PDC reports and preserve automation/state/editor controls through native saves.

The host dependency is pinned `vst3-host` 0.9.0, default audio backend/isolation features disabled, MIT. The exact crates.io source and notices are retained under `vendor/vst3-host`. Two reviewed files add an explicit in-process transport seek and incremental musical-clock advance across tempo changes; other original files retain their recorded hashes. Omatainer provides its own worker, broker and callback exchange because the SDK wrapper takes internal locks. Binding notices missing from their published crate are retained from its immutable upstream revision. `node scripts/license-inventory.mjs refresh|check` maintains the existing dependency/source/notice inventory without Python execution and refuses changed toolchain rights or unknown notices.

Qualification uses private, locally built aarch64 bundles: Steinberg SDK 3.8.1 AGain Sample Accurate and Advanced Tutorial classes (MIT), DISTRHO Nekobi (GPL-2.0-or-later) and MVerb (GPL-3.0-or-later). Those binaries and their sound assets are not included in Omatainer. Omatainer's worker exercised SDK sample-accurate gain interpolation, opaque-state reopen and version refusal, Nekobi note audio and MVerb audio/tails. Authored aborting, hanging and invalid-factory ELF fixtures exercise real plugin failures. Scanner tests cover quarantine, unchanged cache, blacklist, cancellation and reopen. Native egui/AccessKit verifies controls, protected-mode refusal and durable blacklist reopen. Callback fixtures verify exact bridge delay, first-sample MIDI/automation, late-worker silence and zero callback allocation; a paced native SDK bridge fixture verifies delayed impulse samples and state capture.

Native editor behavior, physical audibility, app graph/project integration, current third-party authorization dialogs and installed release workflows remain unqualified. No SDK-validator result is represented as Omatainer hosting proof. Source/binary hashes and exact test receipts are in [vst3-core-receipt.json](vst3-core-receipt.json).

Graph/project integration now has a separate [native routing and state qualification](vst3-graph.md). The foundation boundaries above describe that earlier milestone.
