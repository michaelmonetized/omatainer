# Complete DJ library backup and restore

The Library window opens Back up and restore DJ library. Export captures one immutable saved catalog; later owner edits cannot change it. Normal export collects metadata only. An explicit checkbox authorizes all current local catalog tracks within a chosen 1–1024 GiB total and 8 GiB per-file limit. Duplicate encoded bytes share one backup asset. Originals remain read-only; provider music is not copied.

The version-1 backup contains a schema-12 catalog and a strict manifest. Encoded sources use same-descriptor fingerprints, mount guards, SHA-256 and bounded 64 KiB reads. Both metadata documents are limited to 64 MiB. Validation rejects unsupported schemas, unknown fields, duplicate IDs, undeclared files, symlinks, traversal names, corrupt payloads, changed sources and exceeded limits. Metadata serialization is bounded while writing. One worker and one request/result slot keep all file work and captured-catalog retirement off the GUI.

Restore verifies the entire backup, then privately copies collected assets to a distinct path for each stable track identity. Current cues, grids, analysis, tags, annotations, locks, crates, favorites and history remain attached; prior source/version fingerprints remain archived. A full relocation history or catalog version budget rejects the whole candidate. New directories publish atomically without replacing an existing pathname. Writes report committed directory-sync warnings separately from pre-publication failure. Native input revisions fence old actions after paths or authorization change. User cancellation and performance protection stop optional work before publication.

Import is explicit through the existing catalog owner. All conflicting identities, locations and crate structures are checked before live mutation. Restore neither activates foreign watched roots nor starts playback. The original backup remains read-only.
