# Continuous ordered-crate playback — #200

Open **continuous…** in the library toolbar. Choose a manual ordered crate separately for deck A or B, enable **Repeat ordered crate** if wanted, and switch on **Enable continuous playback**. Each enabled deck captures the crate's stable member order. The panel shows its next title, active state, current result and the sixteen most recent skipped sources.

A playing track finishes before the next crate member loads. A paused member of that crate resumes through ordinary Play; a quiet source outside the crate loads the first member instead. Empty or smart crates are refused. Finite playback stops after the last member. Repeat returns to the first member, but an entire pass with no readable track stops and reports the failures. Catalog/index preparation waits without file reads on the GUI. Native source and fingerprint checks, decode, cancellation and protected load admission use the existing loader and renderer receipts.

Native load-target controls have distinct **Load target deck A/B** accessible names, separate from static deck headings.

Only an actual forward end of the current source advances the crate. Pause, preview, a manual seek, reverse motion, scratching and loop wraps cannot masquerade as natural ends. The renderer acknowledges the start with the exact pre-start end counter, so a very short track ending inside its first audio block is still observed. Duplicate queued requests preserve the first acknowledgement.

Disable immediately revokes the run's start lease and cancels only its own still-current pending decoder and load receipt. A manual track or transport change ends automatic ownership. Pending starts require the same applied media, manual transport generation and safety epoch, with a paused untouched deck outside preview. Outer playback rejection and unapplied command retirement settle the acknowledgement. The original run and its fixed request storage retire on the existing worker; dropping the native owner before rendering cannot free that storage inside the audio callback.

Current playback, another deck, master, gains, pitch, crossfader and monitoring remain under their ordinary manual controls. Continuous mode is transient and is absent from saved project/profile data; a new app instance starts disabled. There is no automatic beatmatching or crossfader mixing.
