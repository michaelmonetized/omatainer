# Song MIDI clock output

Issue [#147](https://github.com/michaelmonetized/omatainer/issues/147) adds MIDI clock and transport output from the native song audio renderer. In **Preferences → MIDI clock output**, enable **Send song MIDI clock**, choose 1–8 independent output destinations and set compensation from −500 to +500 ms. Save the profile to apply the reviewed policy. The saved policy survives profile reopening; old profiles migrate with clock output disabled. Exact unique output IDs prevent ambiguous names from opening the wrong instrument. Clock output does not use track MIDI routes or broadcast to every discovered device.

Clocks run at 24 pulses per quarter note. Song Play at the beginning sends Start before the first clock; starting elsewhere sends a 14-bit Song Position followed by Continue. Song position has six-clock/sixteenth-note resolution and is rounded down when the song lies between these positions. A fresh start past beat 4095.75 refuses visibly; an already-running song can continue beyond that boundary. Stop, explicit song movement and loop wraps produce ordered transport messages at their actual rendered sample boundaries. Count-in does not start the external transport. The scheduler follows native tempo steps and ramps; Session and Arrangement share this song clock. DJ decks retain their separate transport.

The bounded renderer scheduler performs no backend sends, allocation or locks. One output worker owns destination connections and schedules their messages against the first output sample's reported playback timestamp. Without a backend timestamp it estimates one buffer ahead and marks timing as estimated. Compensation shifts those deadlines. Negative compensation can only advance messages within the audio callback's available lookahead; messages whose deadlines have already passed are sent immediately and reported as late. The Sync panel shows prepared song state, selected destinations, scheduled/sent clocks, late sends, worst send-completion delay, queue overflow and actual errors. Sent counts represent messages accepted by all selected output backends, not proof of physical instrument reception or phase.

Change enabled destinations or compensation with song playback stopped. The worker refuses a running change and retains the applied policy. Disabling remains available while running and sends Stop. Cancelled discovery and missing/ambiguous ports preserve the previous policy. Queue overflow, output failure, emergency recovery and a missing audio callback stop clock scheduling; the worker attempts Stop on every selected destination, even when audio callbacks have ceased. Output errors cannot confirm physical Stop. Recovery requires **Retry saved MIDI clock** after resolving the fault. Echoed Start/Continue/Stop from active or recently retired output devices are ignored by the MIDI input transport path to prevent a return cable from stopping or restarting the song.

Preference schema 21 persists the independent output policy. Older headers reject injected clock settings, including null, instead of silently discarding them. Native editing, exact destination selection, compensation and real profile-file reopening are checked through egui/AccessKit controls. Qualification uses the production audio renderer and clock output worker with deterministic backend fixtures; it opens no physical MIDI or audio devices and leaves the stage app untouched. Physical drum-machine synchronization remains an explicitly unperformed acceptance check.

Protocol references: [MIDI Association message summary](https://midi.org/summary-of-midi-1-0-messages) and [system/realtime message behavior](https://midi.org/about-midi-part-3midi-messages).
