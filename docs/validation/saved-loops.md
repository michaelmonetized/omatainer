# Saved loop banks

Each exact track version now keeps eight named loop slots. IDs 1–8 stay fixed when their display order changes, a slot is deleted or a new region replaces it. Names accept up to 64 UTF-8 bytes and reject control characters. Existing slot colors survive persistence; this editor adds names and ordering without a new color chooser.

Open a deck’s existing Loop editor to save its current region, recall a slot, activate it, rename it, move it or delete it. Recall prepares the region and disables looping while preserving the playhead. Activate jumps to the saved start and enables looping; neither action starts a stopped deck. Move changes display order only. MIDI learn and portable presets expose Recall, Save and Delete against a fixed slot ID. The Pioneer decoder’s existing saved-loop addresses use this bank through the same commands.

Loop regions use decoded source seconds. Recalls keep exact endpoints across output-rate changes and manual tempo anchors. An enabled deck quantization setting queues activation at the next actual musical sample boundary, retaining the current saved tuple and source identity. Rename, deletion, other loop edits, source replacement, routing/cancellation changes, scratch/reverse and safety recovery retire stale queued work. Saving refuses temporary roll/slice loops, stale media, nonfinite endpoints, regions shorter than 64 source frames and regions extending outside the decoded source.

The fixed-size preparation receipt publishes slot regions, names, colors, selected ID and order with existing cue/grid/gain metadata. Native project state 24, library schema 16, MIDI preset 4 and preferences 22 persist the complete bank. Older formats migrate default empty banks and existing assignments; older headers carrying the new fields/actions are refused, including injected null or default bank fields. Native project validation refuses slots outside their embedded source. Library loading retains only valid in-source regions for that exact media version.

Normal track reload restores the selected slot and current armed loop while transport remains stopped. Opening a native project follows its existing stopped-transport policy and restores the bank plus armed region; queued activation is never resumed. Save, rename, reorder, recall, activate and delete share the deck’s native Undo history and library metadata publication, including inverse restoration after source changes. Existing library backup, restore and merge retain the bank and stable track identity without rewriting audio files or tags.

The workflow was compared with [Serato’s managing loops documentation](https://support.serato.com/hc/en-us/articles/226383867-Managing-Loops), including stored slots and activation from their start. This is software qualification on Linux ARM64: native egui/AccessKit editing, the actual renderer and MIDI input worker with synthetic messages, real native project/catalog/backup/preset/settings files, independent stereo loop output and musical-boundary oracles, strict migrations and callback allocation measurements. It opens no physical audio or MIDI device and makes no new physical controller qualification claim.
