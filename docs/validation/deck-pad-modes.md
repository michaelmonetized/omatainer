# Deck performance pads — #192

Each deck now has the same eight fixed pad IDs in eight selectable modes: Hot Cue, Roll, Slice, Sampler, Saved Loop, Auto Loop, Manual Loop and Velocity Sampler. This uses the functions already present in Omatainer's SP1 decoder, with one command surface shared by the native deck and learned MIDI assignments. The two decks select modes independently. Named hot cues and saved loops retain their colors; other modes have fixed colors, current labels and applied state. The right sampler deck addresses slots 9–16. Parameter buttons show their actual operation: roll/auto-loop size, slice subdivision and shifted domain, sampler bank, or loop length/move. Modes addressing loops use the current media-qualified region; no selector implicitly starts a stopped deck.

A pad press captures its input source, physical key, original deck and action. Mode changes release only that deck's pad-owned gestures and retain a physical-key tombstone until the corresponding release. Ordinary Cue, reverse, sampler and another deck/input's held controls stay independently owned. Manufacturer mode and deck-layer note addresses normalize to the SP1's original physical pad. Learned note-offs resolve the raw key before profile lookup. The existing MIDI worker retires its own reservations when its profile changes or input disconnects. Safety retires the whole admission epoch and clears renderer ownership for a fresh post-recovery press. No synthetic source IDs or unbounded callback maps are used.

Every accepted onset reserves its release capacity in the normal CommandPort queue. Invalid deck/slot/velocity inputs are refused before admission. Native mouse, Space, Enter, assistive and touch holds have separate stable raw keys; release outside the pad, focus loss, media replacement and project/safety boundaries retire the original input. Touch keeps its existing 32-contact limit while the bounded hit list includes both deck-pad grids and the sampler. Accessible pulse, explicit press/release and Hot Cue delete/editor actions use the actual handlers.

MIDI learn adds fixed pad IDs, named mode selectors and four parameter actions. Connected profiles advertise mode names/colors from their validated selector bindings, while the reviewed factory SP1 map advertises its eight implemented modes. Portable definitions carry these declarations. Preset version 5 and preferences version 23 persist them; older headers refuse the new actions instead of silently injecting newer behavior. Supported older preferences migrate in memory. Supported older portable definitions preserve their format version and remain usable. Reopening does not restore held input.
