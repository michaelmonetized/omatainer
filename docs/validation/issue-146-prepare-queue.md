# Prepare upcoming tracks

Library **prepare…** holds up to 4096 upcoming stable track identities and 2 MiB of references. Queue the selected browser row or the captured filtered crate; changing navigation after admission cannot retarget hardware requests. Repeated identities retain their captured version and original position. A stale row or exceeded bound rejects the whole addition, including healthy prefixes.

Move the selected prepared track up/down or remove it. Loads use the ordinary captured deck review, performance protection, decoder and renderer receipts. The incoming file fingerprint is checked against the opened regular file before decoding and checked again afterward. Changed or failed media preserves both the playing deck and the queue entry.

A prepared track already loaded on a paused deck can preview through that deck's existing output. Preview neither sets Play nor records a source-play onset. It advances at the active pitch/keylock rate; Stop preview restores the original position. Play, Cue, touch, position/loop controls, replacement, safety stop, output recovery and closing the queue stop preview. Project capture retains the original position rather than the temporary preview position. No separate headphone route is inferred from this operation.

Remove-after-play uses the existing conservative classification of final converted digital main output. It requires one complete 10 ms activity window while that version's deck is playing, beginning after queue admission. Load acknowledgment, paused preview, silence, partial windows, ambiguous/nonfinite observations, old receipts and direct renderer exports cannot remove it. Retain keeps entries until manual removal. Transient monitoring uses preallocated callback storage and coherent atomic receipts; it does not start a persistent performance-history session or send session-zero events to its consumer.

Save creates one ordered manual crate through one atomic catalog-owner save. The queue remains available while its durable receipt arrives. Failed persistence before replacement restores the prior catalog; unknown or unconfirmed durability remains explicit. Save does not navigate the browser. Restore selected named crate or Restore last saved queue explicitly replaces the queue with that crate's current catalog versions and saved order. Empty, oversized, automatic or unavailable crates reject without changing the queue. The transient queue and its retention choice are not silently persisted in a project.

Dedicated Prepare/PrepareCrate MIDI actions use the bounded existing control-to-GUI mailbox. On profiles with mapped Shift and Load controls, shifted deck A Load prepares the selected track and shifted deck B Load prepares the captured filtered crate. Captures are limited to 4096 references and 2 MiB per request on the existing MIDI dispatch worker; the raw MIDI/audio callbacks never resolve browser storage.
