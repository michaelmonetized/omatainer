# DJ benchmark research and scope

Research date: **2026-09-30**. Repository baseline: [`cae546c7bc840ec1a643e4befe18f91e86d0e4c7`](https://github.com/michaelmonetized/omatainer/tree/cae546c7bc840ec1a643e4befe18f91e86d0e4c7). The DJ manifest contains **99 atomic feature proposals**, each with official benchmark sources, a current repository limitation, acceptance criteria, validation needs and dependency IDs. `dj-source-registry.json` records the full source catalog. These are researched product gaps, not claims that competitor software or physical hardware was exercised in this audit.

## Stable release and preview boundary

The official download page identifies **Serato DJ Pro 4.0.10** as the latest release. Its release notes add Hercules DJControl T10 support; the feature description introduces Stem Slip. The same page includes model-specific connection, display, MIDI mapping and history corrections, illustrating why compatibility must be qualified per device and operation. [Serato download and release notes](https://serato.com/dj/pro/downloads).

**Serato DJ 5.0 is a public beta**, announced September 10, 2026. Automatic changing-tempo analysis under Lucid Beatgrids, concurrent provider use under Open Streaming, and combined Cue Loops are explicitly preview comparisons in `dj-automatic-variable-grids`, `dj-multi-provider-streaming` and `dj-cue-loops`. The announcement also identifies returning M3U/M3U8 import; standard playlist interoperability is proposed Omatainer scope and is not presented as stable 4.0 parity. [Official 5.0 beta announcement](https://the-drop.serato.com/announcements/introducing-lucid-beatgrids-in-serato-dj-5-0/).

Manual mapping of tempo changes is already documented in the stable manual. It must not be confused with beta automatic tempo tracking. [Beat Warp Markers](https://support.serato.com/hc/en-us/articles/227626968-Beat-Warp-Markers).

## Core, entitlement and hardware distinctions

Stable core comparisons include library management, beatgrids, cues, loops, sync and supported performance workflows. The exact available deck count, pad modes, controller displays, motorized response and audio controls depend on hardware and configuration. A supported Serato device is not evidence that its complete protocol or Linux driver is available to Omatainer. [Display Modes](https://support.serato.com/hc/en-us/articles/225122768-Display-Modes), [hardware licensing](https://support.serato.com/hc/en-us/articles/202260274-Understanding-Serato-DJ-compatible-hardware-licensing), [HID media players](https://support.serato.com/hc/en-us/articles/115002472573-Using-Serato-DJ-CDJ-s-Media-players-with-HID-mode).

Serato lists **DVS, Pitch ’n Time DJ, Play, FX, Flip and Video** as expansions. Their analogues are marked optional or entitlement-dependent in the backlog. DVS requires a usable control-signal format and supported input hardware; this backlog does not assume a license to NoiseMap. Pitch ’n Time is a benchmark for time stretching, key shift/sync and Pitch Play, not a proposed dependency on its proprietary algorithm. Flip supplies reusable cue/censor routines. Video covers synchronized visuals and karaoke; platform-specific output such as Syphon is not promised on Linux. [Official expansions](https://serato.com/dj/pro/expansions).

The current FX FAQ documents 23 built-in DJ-FX and four built-in Channel FX, with additional effects and advanced preset editing depending on entitlement. Channel FX require appropriate hardware **or Serato Play**. The feature issues ask for useful, testable effect behavior, not copies of proprietary effect implementations. [DJ-FX and Channel FX FAQ](https://support.serato.com/hc/en-us/articles/10245865629583-3-2-0-DJ-FX-Channel-FX-FAQ).

Motor platters, dual-computer selection, Stem Slip, booth/microphone controls and performance gestures use current device manuals as concrete benchmarks. Individual hardware guides are evidence for those models only. Physical-device qualification remains required. [Hercules T10 guide](https://support.serato.com/hc/en-us/articles/17616872214799-Hercules-DJControl-T10-Quickstart-Guide-for-Serato-DJ-Pro), [RANE FOUR guide](https://support.serato.com/hc/en-us/articles/10173644318351-RANE-FOUR-Quickstart-Guide).

## Streaming provider boundaries

Provider integration proposals are conditional on authorized access, current commercial terms and a technically supported platform. A web metadata API does not grant DJ audio playback, offline caching, recording or extraction rights. The framework and continuity issues explicitly enforce per-provider capabilities.

| Provider benchmark | Documented boundary affecting implementation |
| --- | --- |
| Spotify | Premium account; current Serato FAQ limits use to two decks and excludes offline playback, recording and Stems. [Spotify FAQ](https://support.serato.com/hc/en-us/articles/13442331645711-Serato-DJ-Spotify-Frequently-Asked-Questions) |
| Apple Music | Internet required; streamed tracks cannot be recorded or used with Stems. Local purchased/imported files and cloud streaming are distinct workflows. [Apple Music FAQ](https://support.serato.com/hc/en-us/articles/12188545880719-Serato-DJ-Apple-Music-streaming-Frequently-Asked-Questions) |
| TIDAL | DJ entitlement, version-dependent Stems support, no offline locker and no set recording of streamed tracks. [TIDAL FAQ](https://support.serato.com/hc/en-us/articles/360000588435-Serato-DJ-Pro-Tidal-Music-Frequently-Asked-Questions) |
| SoundCloud | Appropriate subscription/region and DJ-app track availability; network dependence and recording restrictions. [SoundCloud FAQ](https://support.serato.com/hc/en-us/articles/360000648075-Serato-DJ-Pro-SoundCloud-Frequently-Asked-Questions) |
| Beatport | Plan-dependent offline locker, complete authorized cache readiness and recording restrictions; current documentation also covers Beatsource migration. [Beatport FAQ](https://support.serato.com/hc/en-us/articles/360001929056-Beatport-Streaming-FAQ) |

Provider documents can lag release-level library changes. Older setup articles describing a categorical ban on mixing local and streamed tracks in crates were not treated as universal current restrictions. Concurrent *different-provider* playback is separately classified against 5.0 beta. Integration implementations must refresh entitlement and API evidence before shipping.

## Repository maturity and issue boundaries

Current Omatainer has two decks, transient hot cues and one loop per deck, scalar BPM estimation, colored waveforms, a hardcoded crossfader response, builtin sample banks, synthesized instruments and static MIDI maps. Those partial implementations are acknowledged; the backlog does not describe every corresponding capability as nonexistent. In particular, loop in/out/reloop already snap against a zero-origin scalar-BPM grid, and DeckMatch performs one-shot modulo-beat alignment when both decks are playing. The new quantization/sync scope adds persistent musical grids, variable tempo, deliberate leader rules and sustained synchronization. [Loop snapping](https://github.com/michaelmonetized/omatainer/blob/cae546c7bc840ec1a643e4befe18f91e86d0e4c7/src/engine/mod.rs#L1175), [DeckMatch](https://github.com/michaelmonetized/omatainer/blob/cae546c7bc840ec1a643e4befe18f91e86d0e4c7/src/engine/mod.rs#L1392).

The P0 headphone issue owns the existing program-isolation failure as well as complete monitoring behavior: the render loop blends cue material into its sole program stereo pair. Acceptance requires independent program and headphone paths, followed by real multichannel capture. [Current cue blend](https://github.com/michaelmonetized/omatainer/blob/cae546c7bc840ec1a643e4befe18f91e86d0e4c7/src/engine/mod.rs#L732).

MIDI learn owns the complete currently ignored LearnCapture workflow. Full clock input/output follows the repository's own hybrid-performance claim and the MIDI standard; it is not attributed to arbitrary Serato clock support. Narrow MIDI parser, relative-jog, load bridge, connection-label and controller-map defects remain in fix issues, with feature dependencies. [Repository clock claim](https://github.com/michaelmonetized/omatainer/blob/cae546c7bc840ec1a643e4befe18f91e86d0e4c7/README.md#L41), [MIDI 1.0 specifications](https://midi.org/midi-1-0-core-specifications).

The persistent DJ library is separate from native DAW project persistence. DJ sampler banks are separate from editable production sampler instruments and drum racks. Live stem performance depends on shared production separation infrastructure; it adds live transport, cached readiness, deck/pad controls and per-stem routing. Generic audio devices/routing, project recovery, plugins and global safety belong to platform issues. Ableton Link and production editing belong to production issues. SoundSwitch is an independent optional lighting ecosystem, not a Serato core feature or a promise of Linux support. [SoundSwitch compatibility](https://support.soundswitch.com/en/support/solutions/articles/69000847104-soundswitch-dj-software-compatibility-with-soundswitch).

Coverage includes deck layouts and grids; tempo, pitch and harmonic controls; cues, loops and pads; Stems; DJ sampler and effects; MIDI learn, mappings, clock and hardware; DVS/HID/motorized control; headphone/booth/external mixing and microphone inputs; durable library, tags, crates, analysis, relocation and history; providers and offline lockers; recording/broadcast; optional Flip-like routines, video and lighting; and explicitly labeled preview comparisons. Acceptance criteria and validation thresholds are proposed Omatainer requirements rather than assertions that Serato implements identical internal behavior.
